# ADR-001 — Exact monetary representations

Status: Implemented in component source; partial SQL source unexecuted.

## Decision
Use signed long/BIGINT for stored minor units and decimal integer strings for JSON. Parse decimal entry exactly with BigInteger/BigInt and fixed currency exponents.

## Consequences and alternatives
Floating-point introduces rounding; binary-decimal conversion is not an acceptable financial normalization. Strings avoid JavaScript Number limitations. The cost is explicit DTO validation/formatting across every boundary. Cross-row aggregate sums use NUMERIC/BigInteger. Browser-to-ledger proof remains absent.
